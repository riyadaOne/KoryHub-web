# نهايات الأسطر في Git

في Windows، يمكن أن يغيّر Git نهايات أسطر الملفات (`LF` ↔ `CRLF`). يقارن KoryHub الملفات **بايتًا ببايت**: الملف الذي تغيّرت نهايات أسطره وحدها يُعدّ معدَّلًا.

## العَرَض

بعد `git clone` أو `git checkout`، يشير `kory update` أو `kory remove` إلى ملفات «عدّلتها أنت» مع أنك لم تلمسها.

## السبب

الإعداد `core.autocrlf=true`، الشائع في Windows، يحوّل نهايات الأسطر عند الاستخراج. فلا تعود الملفات التي كتبها `kory pull` مطابقة لملفات kory.

## الإعداد الموصى به

اطلب من Git ألا يحوّل أبدًا الملفات التي ثبّتها kory. في الملف `.gitattributes` في جذر المشروع، أضف سطرًا لكل مجلد تثبيت:

```
src/Payments/** -text
```

ثم اجعل Git يعيد قراءة الملفات:

```
git add --renormalize .
```

## ما يقارنه KoryHub

تُحسب البصمات في `kory.lock` على البايتات الدقيقة لكل ملف، دون أي تحويل. وبهذا يعرف KoryHub بيقين ما إذا كنت قد عدّلت ملفًا.
